# Dark Echo — BGM(楽曲)制作指示書 第2版(全面作り直し)

> 対象リポジトリ: `s1-1985/Dark-Higgs`(公開)
> 目的: ChatGPT に BGM を**全部作り直して**もらい、Claude(コード担当)がゲームへ組み込む。
> 前の版: `docs/BGM_SPEC_v1.md`(第1版・今ゲームで流れている曲の指示書)。**第2版はこの文書だけを正とする。**
> 効果音は別紙 `docs/SE_SPEC.md`(第3版)。**コンセプトは効果音と同じ**(§0.2)。
> 表記: 「**事実**」= ゲームのコードや音声ファイルの計測で確認した内容 / 「**推論**」= 確認していない見立て。

## 0. 最初に読むこと

### 0.1 なぜ作り直すのか(オーナーの評価と計測の事実)

オーナー(ゲームの作者)の評価:
- 「基本的にずーっと低く暗めの音なので**代わり映えがなさすぎる**。全体的にどれも似ている」
- 「戦闘時・警告時・逃げて隠れている時など、**状況に応じて緊張感・緊迫感・戦闘時の高揚感**など、シーンを盛り上げるBGMにして」
- 「大事なのは状況が変わった時の曲の切り替え。状況がコロコロ変わるので、そのたびに急に曲が変わると不自然。**違和感なくフェードアウト・フェードインして切り替えて**」

第1版の17曲を計測した結果(**事実**・Claudeが周波数と音の立ち上がりを測った):

| 計測 | 結果 | 意味(推論) |
|---|---|---|
| 音の重心(スペクトルの重心) | **全曲 98〜189Hz** | 全部が同じ低い唸りに聞こえる |
| 150Hz 未満のエネルギー | 静穏・受信・照射・交戦・タイトルとも **85〜92%** | 低音だけで、曲ごとの色が無い |
| 2kHz 以上のエネルギー | **全曲 ほぼ 0%**(最大 0.6%) | きらめき・刻み・空気感が無い |
| 音の立ち上がり(リズムの手応え) | 交戦曲でも **毎秒 0.2 回**(静穏などは 0) | 交戦でも拍が感じられず高揚しない |
| 音量(RMS) | 交戦曲は静穏の約 **2 倍** だけ | 場面が変わっても盛り上がりの差が小さい |

第1版で「中音域を空ける・メロディを出さない・ダイナミクスを一定に」を強く指示したことが、**全部が同じ低いドローンになった**原因と考えている(推論)。第2版ではこの制約を**緩める**(§0.3)。

### 0.2 コンセプト(効果音と同じ)

**宇宙・近未来・SF・重厚・クール・戦闘・巨大な宇宙戦艦。** これを想起させる曲。

- **重厚・巨大さ**(低い側): 低い金管(トロンボーン・チューバ・ホルンの重い和音)、低弦のオスティナート、大太鼓・タイコ・ハイブリッドな打楽器、シンセのサブベース、巨大な金属の響き。
- **近未来・SF・クール**(高い側): アルペジオのシンセ、パルス状の電子音、きらめくパッド、ガラスのような高い倍音、グリッチ、フィルターが開いていく音、遠くのテレメトリ音。
- **基本はハイブリッド・オーケストラ+エレクトロニクス**(大作のSF映画・SFゲームの戦闘曲の質感)。場面ごとにオーケストラ寄り/電子寄りの比率を変えて**曲ごとの色をはっきり変える**。
- 暗く、冷たく、緊張感がある世界。ただし**戦闘では高揚させる**(英雄的に勝ち誇る旋律ではなく、「巨大な艦同士が撃ち合う迫力」)。

**禁止**:
- 8bit・チップチューン・レトロゲーム風。軽いポップス・EDMのドロップ・ギターのロック。
- 歌詞のある声(声を使うなら無歌詞の合唱・ヴォカリーズのみ)。
- 第三者の楽曲・既存作品の旋律の引用やサンプリング・特定の作品に似せすぎること。
- **全曲が同じ低い唸りになること**(第1版の失敗)。

### 0.3 効果音との共存(第1版より緩める)

このゲームは効果音が情報(ソナー・警報・被弾)を伝える。BGMは邪魔をしないが、**萎縮しすぎない**。

- **長く伸ばす主旋律・持続音を 900〜1400Hz に置き続けない**(ソナーの基音の帯域)。ここを短く通る・刻むのはよい。
- それ以外の帯域は自由に使ってよい(**高域のきらめきや刻みは積極的に使う**)。
- 音量差は場面ごとに大きくつける(§1 のラウドネス)。曲の中の強弱(4〜8小節の起伏)もつけてよい。ゲームは効果音が鳴る時に BGM を自動で少し下げる。

### 0.4 曲を違和感なく切り替えるための約束(最重要)

**事実**: ゲームは状況が変わるたびに曲を切り替える(状況は数十秒〜数分で頻繁に変わる)。第2版では、ゲーム側で次のように切り替える(Claude が実装済み):

1. **試合中の曲は全部 同じテンポ・同じ長さ・同じ和声の骨格**にしてもらう(下表)。
2. ゲームは、今の曲の**小節の位置のまま**次の曲を重ねて始める(例: 今の曲の 13 小節目にいれば、次の曲も 13 小節目から鳴り始める)。**拍・小節・和音がずれずに入れ替わる**。
3. 切り替えは**等パワーのクロスフェード**。上がる時(発見・交戦・逃走へ)は次の拍で 2.5〜3 秒、それ以外は次の小節で 新しい曲が 5 秒で上がり・古い曲が 7 秒で消える。一度切り替えたら 15 秒は次の切り替えをしない(上がる時は除く)。

このため、**試合中の曲(§3.1)は全て次を厳守**:

| 項目 | 指定 |
|---|---|
| テンポ | **120 BPM 固定**(全曲同じ。静かな曲は**ハーフタイム**=体感60で作る。テンポは変えない) |
| 拍子 | 4/4 |
| 調 | **D(ニ)が中心**。D エオリアン(自然短音階)を基本に、場面で D ドリアン・D フリジアンの色を使ってよい。**他の調へ転調しない** |
| 長さ | **32 小節 = 64.000 秒** + 最後に**残響の尾 1 小節(2.000 秒)** = **ファイルは 66.000 秒**。33 小節目は音を新しく鳴らさず、残響が自然に消えていくだけ(ゲームが 32 小節で次の周を重ねて始める) |
| 和声の骨格 | **8 小節の進行を 4 回**(全曲共通): `| Dm | Dm | B♭ | B♭ | C | C | Gm | A |`(A は A sus4 → A でも可)。静かな曲は D の持続音の上でこの骨格を**ほのめかすだけ**でよい(和音を全部鳴らさなくてよい)。**骨格と矛盾する和音を鳴らさない**(重ねた時に濁るため) |
| 頭 | 1 小節目の 1 拍目から音楽が始まる(頭の無音 5ms 以内)。**1 小節目に大きなアクセントを置かない**(途中から入ることが多いため。曲のどこから始まっても成立するように) |
| ループ | 32 小節目の終わりから 1 小節目へ自然につながる(2 周つなげて聴いて違和感がない) |

試合の外の曲(§3.3)とスティンガー(§3.2)は、この制約をゆるめてよい(各表に記載)。

## 1. ファイル仕様

| 項目 | 指定 |
|---|---|
| 形式 | **WAV(PCM 16bit)・48kHz・ステレオ** |
| ピーク | **トゥルーピーク −1dBFS 以下・クリップ禁止** |
| ラウドネス(統合) | 潜伏 **−28 LUFS** / 探索 **−25** / 受信 **−23** / 発見 **−20** / 逃走 **−18** / 交戦 **−16**(差をはっきりつける)。凪・サージ −24。タイトル −20。ドック・リザルト −24 |

| 総量の目安 | 1 秒あたり約 192KB。WAV の総量 400MB 以内(Claude が MP3 に変換して入れる) |

## 2. 納品の仕方(効果音と同じ)

1. **ZIP で納品**: `Dark-Higgs_BGM_v2_Part01.zip`、`…_Part02.zip` …(1つ 50MB 以内なら分割可)。中身は WAV と `list_PartNN.txt`。
2. `list_PartNN.txt` は 1 行 1 ファイル: `ID<TAB>ファイル名<TAB>長さ秒<TAB>BPM<TAB>小節数(尾を除く)<TAB>尾の秒<TAB>一言メモ`(例: `bgm_calm_loop	bgm_calm_loop_1.wav	66.000	120	32	2.000	探索A`)。スティンガーは小節数と尾を 0 でよい。
3. オーナーが ZIP を Claude に渡す。Claude が MP3 に変換し `prototype/assets/bgm_v2/` に置く。**ChatGPT はリポジトリに書き込まなくてよい**。
4. 納品の順: **P0 → P1 → P2**。途中まで届いた分だけでもゲームで試せる(無い曲は第1版で流れる)。オーナーはメニューの「BGM: 第2版 / 第1版」でいつでも元に戻せる。

### 2.1 納品前の自己点検
1. WAV / 48kHz / 16bit / ステレオ。トゥルーピーク −1dBFS 以下。
2. **試合中の曲は全部 120BPM・66.000 秒・32小節+尾1小節**。
3. **試合中の曲を同じ小節の位置で重ねて聴いても濁らない**(例: 探索と交戦を 13 小節目で 5 秒クロスフェードして聴く。和音・拍がずれない)。
4. ループを 2 周つなげて聴き、継ぎ目に不自然な無音・音切れ・クリックがない。
5. **曲ごとに色がはっきり違う**: 全曲を 10 秒ずつ並べて聴き、どれがどの場面か区別できる。第1版のように**全部が低い唸りに聞こえたら作り直す**。数値の目安: 探索・受信でも 2kHz 以上の成分が聞こえる / 交戦は打楽器の立ち上がりが毎秒 2 回以上。
6. 長い持続音が 900〜1400Hz に居座っていない。
7. 無歌詞。既存の曲に似ていない。

## 4. 組み込み(Claude の作業・ChatGPT は考慮不要)

1. 届いた WAV を MP3 にして `prototype/assets/bgm_v2/` に置き、台帳を作る(テンポ・小節数・尾の秒・テイクを記録)。
2. **実装済み**: 同じテンポ・同じ長さの曲どうしは小節の位置を揃えて等パワーでクロスフェード / 上がる時は次の拍・それ以外は次の小節 / 切り替え後 15 秒は待つ / スティンガーは次の拍 / 別テイクは周回ごとに交互 / 逃走の判定(離脱の道具・緊急噴射・傷が深く追われている)/ 潜伏の判定(機関停止・潜航で受信以上)/ 版の切り替え(第1版へ戻せる)。
3. 聴感の確認はオーナーが実機で行う(Claude は音を聴けない。周波数・立ち上がり・ラウドネスの計測で §2.1 の 5 を機械的に点検する)。
