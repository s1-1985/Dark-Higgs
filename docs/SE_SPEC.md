# Dark Echo — 効果音(SE)制作仕様書

> 対象リポジトリ: `s1-1985/Dark-Higgs` / 基準コミット: `52dc26d`(main)
> 目的: ChatGPT に効果音を作ってもらい、Claude(コード担当)がゲームへ組み込むための受け渡し仕様。
> 行番号は基準コミットの `prototype/game.js` のもの(ずれた場合は関数名で探す)。
> 表記: 「**事実**」= コードで確認した内容 / 「**推論**」= 確認していない見立て。

---

## 0. 読み方(ChatGPT 向けの要約)

1. 作る物は **§4 の SE 一覧**にある音。優先度 **P0 → P1 → P2** の順に納品する(§5)。
2. 納品形式は **WAV / 48 kHz / 16 bit / モノラル**(ループ用の環境音だけステレオ可)。置き場所は `prototype/assets/sfx/`、ブランチは `chatgpt/se-assets`(§6)。
3. 音の方向性は **「宇宙戦艦で潜水艦戦」**: 静かな中に張り詰めた緊張があり、当たれば重い。基準は §2 の「ミサイル直撃」。
4. 同じ出来事でも **聞こえ方を分ける**(自艦の被弾 = 艦内の振動音 / 遠くの命中の探知 = センサーの受信音)。§2.2 と §4 の ID を取り違えないこと。
5. **リバーブは焼き込まない**(ゲーム側で共通の残響を掛ける)。ただし §4 に「余韻」と書いた低い振動の尾は音に含める。

## 1. 現行の再生方式(事実)

| 項目 | 現状 |
|---|---|
| 再生方式 | **Web Audio API の合成のみ**。外部の音声ファイルは1つも使っていない(`prototype/assets/` に音声なし) |
| 入口 | `playSound(type, vol = 1)` @615。`type` は文字列16種(`shoot` と `shoot_kinetic` は同じ音) |
| 共通の経路 | 各音 → `bus` → 圧縮器(threshold −16 dB・ratio 5)+ 短いフィードバック残響(ウェット 0.28)→ 出力。`_sfxInit` @566 |
| 連打の間引き | 同じ `type` は最短 0.04 秒(ui 0.05・shoot 0.03・hit 0.06・explosion 0.08) |
| 距離・方向 | **パンニングなし(モノ)**。距離で音量を変えるのは `enemyPing` だけ(`vol` 引数) |
| 環境音 | `startAmbient` @702: 55 Hz の二重ドローン + 緊張音(露出度2以上で浮上)+ 呼吸の LFO。ランダムな `ambientEcho` を数秒おきに鳴らす。ON/OFF は `localStorage('darkEchoAmbient')` |
| 音量設定 | 環境音の ON/OFF のみ。SE 音量スライダーは**無い** |
| ファイルの読み込み | **無い**(`fetch` + `decodeAudioData` の仕組みは未実装 → §7 で Claude が作る) |
| 配信 | GitHub Pages で `prototype/` を静的配信。ビルド工程なし |

### 1.1 現行コードの問題(事実)

- **自艦の被弾に音が無い**。`notePlayerHit` @2584 と弾の着弾処理 @2976〜2996 に `playSound` が無い(ミサイル・実弾・ビームの被弾はログ・画面の揺れ・文字だけ)。
- **敵への命中にも音が無い**。`'hit'` を鳴らすのは Tech のサーベル命中 @13043 の1箇所だけ。
- **自艦のソナーが UI 音**。`fireOmniSonar` @9759・`fireDirectionalSonar` @9814 は `playSound('ui')`。専用の `'ping'` は哨戒機の探信 @12559 だけ。
- **敵の発砲・発射の音が無い**。`playSound` の呼び出しに敵の射撃は見当たらない(`enemyPing` だけ)。第46弾の記載「敵の発砲は距離で音量を下げる」と現行コードは一致しない。
- **`'alert'` が12箇所で同じ音**(奇襲・高速推進波・サージ予兆・凪予兆・緊急噴射・遭難信号・囮の看破・コロニー喪失・兆候の上昇など)。聞き分けられない。
- **`'ui'` が約70箇所で同じ音**(決定・キャンセル・トグル・選択がすべて同じ)。
- **`'pickup'` は定義だけで呼ばれていない**(コンテナ・難破船・コロニーの取得は無音)。
- **爆発は1種類**。`createExplosion` @5589 が大きさ(8〜50)に関係なく同じ `'explosion'` を鳴らす。
- ミサイル・実弾の通常の着弾と近接爆発(`nearMissBlast`)は `createExplosion` を呼ばない(= 爆発音も無い)。バリアの破壊(@2575)・迎撃(@12017)・機雷・多弾頭・撃沈では爆発音が鳴る。

→ 「SE に不満がある」のは、**音の質**に加えて**音が鳴っていない事象と、事象ごとの聞き分けが無いこと**が大きい(推論)。

## 2. 音の方向性

### 2.1 全体の世界観

- **宇宙戦艦の艦内で、潜水艦のソナー員のように外を聴く**。静かな時間が長く、鳴る時は意味がある。
- 音は3つの「聞こえの世界」に分ける。同じ事象でも世界が違えば別の音にする。

| 世界 | 例 | 質感 |
|---|---|---|
| **A 艦内・船体伝播**(自艦に起きたこと) | 被弾・自艦の発射・自艦の撃沈・機関・損傷 | 近い。低域が太い(30〜200 Hz の振動)・金属の軋み・残響は短い。「骨に響く」 |
| **B センサー受信**(遠くや見えない所のこと) | 視界外の命中の探知・敵の探信音・敵の発射の感知・信号の受信 | 電子的なブリップ・ノイズ混じり・高域が丸い。距離と確度で薄くなる。「耳をすませて拾う」 |
| **C 艦内端末UI** | ボタン・メニュー・ドラフト | 乾いた小さな電子音(短い・残響なし)。決定=上昇 / 取消=下降 / 不可=低い二連 / 警告=金属の二連 で**音程の動きで聞き分ける** |

### 2.2 同じ事象を聞き分ける(必須)

| 事象 | 艦内(A) | 見えている遠景 | センサー受信(B) |
|---|---|---|---|
| ミサイルが当たった | 自艦が被弾 → `hit_player_missile_*` | 見えている敵への命中 → `hit_enemy_visual_missile_*` | 視界外の命中を光・熱で探知 → `det_impact_far_missile`(確度が低ければ `det_impact_far_unsure`) |
| ビームが当たった | `hit_player_beam_*` | `hit_enemy_visual_beam_*` | `det_impact_far_beam` |
| 実弾が当たった | `hit_player_kinetic_*` | `hit_enemy_visual_kinetic_*` | `det_impact_far_kinetic` |
| 敵がミサイルを撃った | — | (見えれば)小さく | 高速推進波を感知 → `alm_missile_launch_detect` |
| 敵がビームを溜めた | — | — | 電力の昇りを感知 → `alm_beam_charge_detect` |
| 敵がこちらを狙った | — | — | 火器管制の照準波 → `alm_fc_lock_loop` |
| ソナー | 自艦が打つ → `sonar_omni_*` / `sonar_dir_*` | — | 敵の探信を受けた → `alm_ping_omni`(方角不明)/ `alm_ping_dir`(方角が分かる)|

> 確度の違い(AI の解析配分で変わる)は**ゲーム側が音量・ローパス・遅延で付ける**。ChatGPT は「確度が高い版」と「不確かな版」だけ用意すればよい(§4 B)。

### 2.3 ミサイル直撃音の基準(戦闘SEの基準にする)

`hit_player_missile_*` を基準として、他の被弾・爆発の重さを揃える。

| 時間 | 要素 | 内容 |
|---|---|---|
| 0〜50 ms | **鋭い金属音** | 装甲板が裂ける・叩かれる高域の過渡(3〜8 kHz)。短く、輪郭がはっきり |
| 30〜400 ms | **重い爆発** | 低域の打撃(40〜120 Hz)+ 圧力波のノイズ(ローパス)。胸に来る重さ |
| 300 ms〜2.5 s | **艦内に残る低い振動** | 30〜60 Hz のサブ + 構造の共鳴・軋み。ゆっくり減衰。 |

- 全長 2.5〜3.0 秒。余韻は自然に消す(切らない)。
- **スマホの小さなスピーカーでは 100 Hz 未満がほぼ出ない**(推論)。サブ成分の 2倍音・3倍音(100〜250 Hz)も入れて「重さ」が伝わるようにする。
- 他の音の「重さ」の目安: 実弾の被弾 = この音の 1/3 程度 / ビームの被弾 = 同等だが焼ける質感 / 撃沈 = この音を超える。

### 2.4 UI 音の音程の約束

| 役割 | 動き | 長さ |
|---|---|---|
| 決定 `ui_confirm` | 上昇する2音(完全5度程度) | 0.2〜0.3 s |
| キャンセル `ui_cancel` | 下降する1音 | 0.15〜0.2 s |
| 不可 `ui_deny` | 低い短音の二連(ブザー寄り・耳に刺さらない) | 0.25 s |
| 警告 `ui_warn` | 金属質の二連(`alm_*` の警報より小さく静か) | 0.4〜0.5 s |
| タップ `ui_tap` | 小さく丸い一音 | 0.06〜0.1 s |
| トグル `ui_toggle_on / off` | 上がる一音 / 下がる一音(ON/OFF が耳で分かる) | 0.1〜0.15 s |

## 3. 受け渡しファイルの仕様

| 項目 | 指定 | 理由 |
|---|---|---|
| 形式 | **WAV(PCM 16 bit)** | 現行の再生は Web Audio。WAV はどの端末でも `decodeAudioData` で読める。配信用の圧縮(Ogg 等)への変換は Claude が組み込み時に判断する |
| サンプルレート | **48 kHz** | Android の Web Audio の標準的な出力レート(推論)。再サンプルの劣化を避ける |
| チャンネル | **モノラル**(`amb_*` のループだけステレオ可) | 現行はパンニングなし。距離の音量はゲーム側で付ける |
| ピーク | 下表(dBFS)。**クリップ禁止・トゥルーピーク −1 dBFS 以下** | 共通の圧縮器(−16 dB)を通るため、ファイル側でリミッターを強く掛けない |
| 無音の頭 | 先頭は **5 ms 以内**から音が始まる(頭の無音を詰める) | 発射・被弾の反応が遅れて聞こえるのを防ぐ |
| 終端 | 単発は **最後を 0 まで自然に減衰**(切れ目のクリックなし) | |
| ループ | 終端と始端が**途切れず繋がる**(ゼロ交差・クロスフェード済み)。**ファイル名に `_loop`**。ファイル長 = ループ1周 | |
| バリエーション | `_v1`, `_v2`… の連番。同じ事象の連続でも毎回同じに聞こえない用 | ゲーム側が毎回ランダムに選び、さらにピッチを ±3% 揺らす |
| リバーブ | **外部の残響は入れない**(ゲーム側で共通の残響が掛かる)。§4 に書いた「余韻」(低い振動の尾)は入れてよい | |
| 命名 | 小文字・数字・`_` のみ。`<ID>_v<番号>.wav`(バリエーションなし = `<ID>.wav`) | |

### 3.1 音量の基準(ファイルのピーク)

| 区分 | ピーク | 該当 |
|---|---|---|
| 最大 | −1 dBFS | 撃沈・大爆発・自艦のミサイル直撃 |
| 大 | −3 dBFS | 被弾全般・ビーム・自艦の発射 |
| 中 | −6 dBFS | 爆発(小〜中)・警報・ソナー |
| 小 | −9 dBFS | 探知・受信・アイテム・ドローン |
| 極小 | −12 dBFS | UI・環境の細かい音 |
| 環境ループ | 統合ラウドネス −26 LUFS 前後 | `amb_*` |

> 同じ区分の中でも音の「密度」で聴感が変わる。**P0 を作ったあと、音量バランスの確認を Claude から依頼する**(§7)。

### 3.2 サイズの目安

- 1秒あたり約 96 KB(48 kHz・16 bit・モノ)。**全 WAV の合計は 25 MB 以内**、P0+P1 は 12 MB 以内を目安にする。
- 環境ループは 30 秒まで。

## 4. SE 一覧

### 凡例

- **状態**: ✅ = 現行で鳴っている(合成)/ ⚠ = 機能はあるが無音、または別の音の流用 / 🆕 = **イベント自体が現行コードに無い**(フックを新設する必要がある。音だけ先に作ってよい)
- **優先**: **P0** = 無いと戦況が分からない(現状無音か、聞き分けが必要)/ **P1** = 体験が大きく変わる / **P2** = あると良い
- **種別**: 単 = 単発 / ル = ループ
- **V** = 要バリエーション数(1 = 不要)
- 「**時間**」は目安(秒)。

### 6.2 `manifest.json` の書式

```json
{
  "version": 1,
  "sounds": [
    {
      "id": "hit_player_missile",
      "files": ["hit_player_missile_v1.wav", "hit_player_missile_v2.wav", "hit_player_missile_v3.wav"],
      "duration_s": 2.8,
      "loop": false,
      "peak_dbfs": -1.0,
      "notes": "0-50ms 金属音 / 30-400ms 爆発 / 300ms-2.5s 艦内の低い振動"
    }
  ]
}
```

- `id` は §4 の ID と**完全に一致**させる(`{s,m,l}` などの展開した ID は、それぞれ別の `id` にする)。
- `files` は実在するファイル名。1つも抜けないこと。

### 6.3 ChatGPT 側の自己点検(納品前)

1. WAV / 48 kHz / 16 bit / モノラル(`amb_*` のみステレオ可)。
2. トゥルーピーク −1 dBFS 以下・クリップなし・DC オフセットなし。
3. 先頭の無音が 5 ms 以内・単発は終端が 0 に収まる。
4. `_loop` は繋ぎ目でクリックが出ない(自分で2周連結して聴く)。
5. バリエーション数が §4 の V と一致。
6. `manifest.json` の `files` が全て存在する。

> 生成の手段は問わない(Python での合成・素材の加工など)。**第三者の音源・サンプルを使わない**こと(権利の問題。ライセンスはオーナーが確認する — 推論: 生成物の利用条件は使うツールごとに違う)。

## 7. 組み込み(Claude の作業・今回は未着手)

ChatGPT の納品後に Claude が行う。ChatGPT は考慮不要だが、設計の前提として共有する。

1. `fetch` + `decodeAudioData` による**サンプルのローダー**を追加(P0 は起動時に先読み、P1/P2 は遅延読み込み)。`playSound(type)` の `type` を ID に拡張し、**ファイルが無い・読めない時は現行の合成にフォールバック**。
2. 呼び出し側の整理: `alert`(12箇所)・`ui`(約70箇所)・`createExplosion` を、§4 の役割別 ID に振り分け。
3. **鳴っていない事象にフックを足す**(§1.1 の「無音」の箇所と、§4 の 🆕)。
4. ゲーム側で付ける処理: ピッチの揺らぎ(±3%)・バリエーションのランダム選択・距離による音量とローパス・視界外命中の確度による音量・遅延・同時発音数の上限。
5. SE 音量スライダーの追加(現状は環境音の ON/OFF のみ)。
6. 配信用の圧縮(Ogg 等)に変換するかは、納品サイズと端末での読み込み時間を見て判断(推論: 合計 25 MB 以内なら WAV のままでも動くが、モバイルの初回読み込みは遅い)。
7. 組み込み後、ヘッドレスで再生エラーがないことを確認。**聴感の音量バランスはオーナーが実機で確認**(Claude は音を聴けない)。
