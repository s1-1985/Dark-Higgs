# Dark Echo — 効果音(SE)制作指示書(第2版)

> 対象リポジトリ: `s1-1985/Dark-Higgs`
> 目的: ChatGPT に効果音を作ってもらい、Claude(コード担当)がゲームへ組み込む。
> **第2版**: 第1版の「音のイメージ」が一行で粗く、似た音が量産された反省から、**場面ごとに「どんな音か」を具体的に書き直した**。
> 表記: 「**事実**」= ゲームのコードで確認した内容 / 「**推論**」= 確認していない見立て。

---

## 0. 最初に読むこと(全体の方針)

### 0.1 ゲームの説明(音の担当者向け)

ヒッグス粒子の霧が満ちた宇宙空間で、**潜水艦戦のように「先に相手を見つけて撃つ」**戦艦ゲーム。プレイヤーは艦内のソナー員のように、センサーで外を聴く。静かな時間が長く、**音が鳴る時は必ず意味がある**。

### 0.2 音の方向性

**「リアル志向で重厚、カッコよく、SF的」**。基準は次の3つ。

1. **ガンダム(宇宙世紀)の劇中効果音の重み**: 重い、質量がある、金属が軋む。ビームは低域の唸りと高域の電離音が重なる。爆発は低い「ドォン」と遠くへ広がる余韻。ミサイルは筒から射出されてから点火する「ボンッ…シュゴォォ」。
2. **実在の兵器・機械の音**: 実弾は**実銃(ライフル・重機関銃・機関砲)の発砲音**。ジェット・ロケットの噴射は実際の噴射音。金属の衝突は実際の金属音。
3. **潜水艦ゲーム(Silent Hunter・Uボート系)のソナー員の世界**: ソナーは長く響く金属的なピン。受信は静かな中に浮かぶブリップ。警報は低く抑制されている。

**禁止(これは出さないこと)**:
- 8bit・チップチューン・レトロゲーム風・電子ゲームの「ピコピコ」「ポコン」「ブッ」。
- ブリキ缶・空き缶を叩いたような軽い金属音、プラスチックの軽い音。
- 音程が**下がっていって尻すぼみに消える**だけの音(ソナーや鐘でやりがち)。
- 軽い・おもちゃ風・アニメ的なSF効果音(「ビビビ」「ピュンピュン」)。
- 同じ音の**ピッチ違い・音量違いのコピー**を別バリエーションとして出すこと。
- 第三者の音源・既存作品の音のサンプリング(権利の問題)。

### 0.3 音の質感の約束(どの音にも共通)

- **三層で作る**: ①最初の鋭い過渡(アタック。0〜50ms) ②胴の部分(中低域の厚み) ③尾(余韻。自然に減衰)。軽い音は①だけになりがち — 重い音ほど②と③を作り込む。
- **低域を必ず入れる**(スマホのスピーカーでは100Hz未満が出ない — 推論。**100〜250Hz にも重さの成分を入れる**)。
- **金属の質感**は共鳴(リング)・軋み・うなりで作る。ノイズだけで金属感を作らない。
- **尾は切らない**。必ず自然に消える。
- **世界の違い**を作り分ける(§0.4)。

### 0.4 聞こえの3つの世界(同じ出来事でも世界が違えば別の音)

| 世界 | 例 | 質感 |
|---|---|---|
| **A 艦内・船体伝播**(自艦に起きたこと) | 自艦の発射・被弾・撃沈・機関 | 近い。低域が太い(30〜200Hzの振動)。金属の軋み。「骨に響く」 |
| **B センサー受信**(遠く・見えない所のこと) | 敵の探信・視界外の命中の探知・信号の受信 | 電子的でノイズ混じり。高域は丸い。距離で薄くなる。「耳をすませて拾う」 |
| **C 艦内端末UI** | ボタン・メニュー | 乾いた小さな音。残響なし。艦内端末の質感(軍用機器の確認音) |

### 0.5 バリエーションの方針(第1版の反省)

- **基本は1音1ファイル**。`_v1` `_v2` は付けない。
- バリエーションが必要なのは、**短い間隔で何度も鳴る音だけ**(実弾の発砲・実弾の被弾・戦闘機の機銃・UIのタップ)。それも各表の「数」欄に書いた数だけ。
- バリエーションは**音色・衝撃の質が聞き分けられる別テイク**にする(同じ音の加工コピーは不可)。

## 1. ファイル仕様

| 項目 | 指定 |
|---|---|
| 形式 | **WAV(PCM 16bit)** |
| サンプルレート | **48 kHz** |
| チャンネル | **モノラル**。ただし **ステレオ可**: `amb_*`(環境音)・`sonar_*`(ソナー)・大爆発(`expl_large`・`ship_*`)・`sys_*`(試合の節目)。ステレオにする時は左右の広がりを活かす |
| ピーク | 下表。**トゥルーピーク −1dBFS 以下・クリップ禁止** |
| 先頭 | 5ms以内に音が始まる(頭の無音を詰める) |
| 終端 | 単発は自然に0へ減衰(切れ目のクリックなし) |
| ループ | **ファイル名に `_loop`**。繋ぎ目でクリックが出ない。ファイル長=ループ1周。始端と終端を重ねて処理(クロスフェード)する |
| 残響 | **「尾込み」と書いた音は、空間の残響を含めて書き出す**(ソナー・大爆発・撃沈・鐘のような音)。それ以外は**乾いたまま**(ゲーム側で短い共通の残響が掛かる)。**ソナーは必ず尾込み**(ゲーム側の残響は0.1〜0.2秒程度しか足せないため、遠くまで響く感じは音源で作る — **第1版でここを指示していなかったのがソナーが貧弱だった原因のひとつ**) |
| 命名 | 小文字・数字・`_` のみ。`<ID>.wav`。バリエーションがある音だけ `<ID>_1.wav` `<ID>_2.wav` |

### 1.1 音量(ファイルのピーク)

| 区分 | ピーク |
|---|---|
| 最大 | −1 dBFS(撃沈・大爆発・自艦のミサイル直撃) |
| 大 | −3 dBFS(被弾全般・ビーム・自艦の発射・ソナー) |
| 中 | −6 dBFS(爆発の小〜中・警報・ドローンの噴射) |
| 小 | −9 dBFS(探知・受信・アイテム・ドローン) |
| 極小 | −12 dBFS(UI・環境の細かい音) |
| 環境ループ | 統合ラウドネス −26 LUFS 前後 |

### 1.2 サイズ

1秒あたり約96KB(48kHz・16bit・モノ)。全体で **40MB以内**を目安。環境ループは40秒まで。

## 2. 納品の優先度と進め方

- **P0**: 戦闘が成立するために最優先(被弾・命中・ソナー・発射・UIの基本)。
- **P1**: 体験が大きく変わる(ドローン・アイテム・取得・警報・状態異常)。
- **P2**: 仕上げ(環境・細かい確認音)。
- 納品は **P0 → P1 → P2 の順**。各優先度で1コミット以上。

## 3. SE一覧と制作指示

### 3.1 ソナー(最重要・やり直し)

> **ソナーの基本の考え方**: 宇宙の闇に放たれる、**遠くまで響く一定の音がスーッと伸びる**金属的な「ピーーーン」。鐘や大きな金属体を打った後のリング(共鳴)のように、**音程は一定のまま長く伸び、ゆっくり静かに溶けていく**。**音程を下げて尻すぼみにしない**(「ポコン」「ブリキ缶」は不可)。
> 参考にする質感: Silent Hunter・Uボート系・『レッドオクトーバーを追え』の**アクティブソナーの「ピーン」**(純音に近い金属音が長く尾を引く)。ただし舞台は宇宙なので、**水中より乾いて冷たく、倍音が静かに瞬き、深い低域の「圧」が一瞬だけ付く**。
> 作り方の例: 約1.1kHz付近の純音に近い基音(+少量の非整数倍音で金属感)を、アタックは短く鋭く(10ms)、そのあと**一定の音量でゆっくり減衰**させ、巨大な空間の長い残響(数秒)で包む。ごく浅い音程のうねり(ビート 1〜2Hz)を重ねると鐘のように響く。

## 4. 納品方法(Git)

| 項目 | 指定 |
|---|---|
| ブランチ | **`chatgpt/se-assets`**(`main` から作る) |
| 置き場所 | **`prototype/assets/sfx/`**(フラット。サブフォルダ不可) |
| 台帳 | **`prototype/assets/sfx/manifest.json`**(下記) |
| 触ってよい範囲 | `prototype/assets/sfx/` 以下のみ。`game.js` / `index.html` / `style.css` / `docs/` は編集しない |
| 納品の単位 | 優先度ごとに1コミット以上(P0 → P1 → P2) |
| 差し替え | 前に納品した音を作り直す時は**同じファイル名で上書き**(古い版を残さない) |

### 4.1 `manifest.json` の書式

```json
{
  "version": 2,
  "sounds": [
    {
      "id": "sonar_omni_mid",
      "files": ["sonar_omni_mid.wav"],
      "duration_s": 4.5,
      "loop": false,
      "channels": 2,
      "peak_dbfs": -3.0,
      "notes": "基音1.1kHz・音程は一定・尾込み(残響約3秒)"
    }
  ]
}
```

`id` は §3 の ID と**完全に一致**させる(`/` や `〜` で並べた ID は、それぞれ別の `id` にする)。`files` は実在するファイル名。

### 4.2 納品前の自己点検

1. WAV / 48kHz / 16bit。モノラル(ステレオ可の音だけステレオ)。
2. トゥルーピーク −1dBFS 以下・クリップなし・DCオフセットなし。
3. 先頭の無音が5ms以内。単発の終端が0に収まる。
4. `_loop` の繋ぎ目でクリックが出ない(2周連結して聴く)。
5. **ソナーは音程が下がっていないか**(一定のまま伸びているか)・**「ポコン」「ブリキ缶」になっていないか**。
6. **バリエーションが「別テイク」になっているか**(ピッチ違いのコピーでないか)。
7. `manifest.json` の `files` が全て存在する。

## 5. 組み込み(Claudeの作業・ChatGPTは考慮不要)

1. `fetch` + `decodeAudioData` のローダーを追加(P0は起動時に先読み、他は遅延読み込み)。ファイルが無い・読めない時は現行の合成にフォールバック。
2. 呼び出し側の整理: `alert`(12箇所)・`ui`(約70箇所)・`createExplosion` を §3 の役割別IDへ。
3. **鳴っていない事象にフックを足す**(被弾・命中・探知・取得・状態異常・ドローン・アイテムなど。**事実**: 現行コードでは自艦の被弾・敵への命中・ソナーの発信・敵の発砲・取得の多くが無音または別の音の流用)。
4. ゲーム側で付ける処理: ピッチの揺らぎ(±3%)・距離による音量とローパス・視界外命中の確度による音量・同時発音数の上限・ループの音量制御(ドローンの数・速さ)。
5. SE音量スライダーを追加。
6. 音量バランスの聴感確認はオーナーが実機で行う(Claudeは音を聴けない)。

## 6. 現行の再生方式(事実・参考)

- 現在は **Web Audio API の合成のみ**(外部の音声ファイルなし)。`playSound(type, vol)` に16種。全てゲーム内で合成した音で、**オーナーが不満**。ファイルが無い間のフォールバックとして残す。
- 共通の経路は「圧縮器 + 0.1〜0.2秒程度の短い残響」。パンニングなし。
- 現状の問題: 自艦の被弾・敵への命中・自艦のソナー・敵の発砲が**無音または別の音の流用**。`alert`が12箇所で同じ音、`ui`が約70箇所で同じ音。
