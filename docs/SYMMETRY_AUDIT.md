# 自機と敵の「差」の洗い出し (第98弾)

オーナー方針: **自機と敵で 条件・行動原理・アルゴリズム を分けない。差をつける要素は何もない。**
ここでは コードを読んで見つけた差を 直した/残っている に分けて記録する。測り方は `tools/mirror_stats.js` (鏡合わせ) と 1対1の決闘 (霧なし・900u)。

## 残っている差 (未対応)
1. **意思決定が2本のコードに分かれている** — 自機COM (`comPilotStep`/`comHunterStep`/`comStratStep`/`comReactItems`/`comGrabStep`…) と 敵 (`Ship.update`の状態機械/`enemyHunterStep`/`enemyStratStep`/`enemyItemsStep`/`enemyGrabStep`…) は別実装で、重み・しきい値を手で揃えているだけ。決定的な差: 
   - 敵は 信号を聞いたら状態が `hunting`→`combat` へ移り、長く収集をしない / 自機COMは「艦でない信号は気配に数えない」(艦影25%未満・確認した囮) と 取りに行く物を続ける。鏡合わせで **ノードの制圧 自機38回 / 敵0回** (攻撃型)・敵の最初の占有が遅い
   - 戦略: 自機COMだけ 収集・ドローンで探る・霧に潜む・圧倒して狩る・Tech建造 / 敵だけ 索敵行・拠点防衛の一部
   - 退く時: 敵は 潜伏 (`_hiding`) の専用の状態 / 自機COMは戦略「霧に潜む」
2. **ドローン** — 自機は `Drone` クラス / 敵は `enemyFighterStep`/`enemyTechStep`/`enemyScoutStep` の別実装 (値は手で揃えている)。空母の決闘は自機が速く勝つ (戦闘機の運用の差の疑い・未確認)
3. **ミサイルの囮に誘われる** — 敵のミサイルだけ 自機のデコイ (`decoys`・デコイ機) に誘引される。自機のミサイルは敵の囮に誘引されない (敵は同種の物を積まない)
4. **ジャミング** — 敵ミサイルの誘導を乱す式 (`jamMissileFactorAt`) と 自機ミサイルの式 (`Projectile.update` の `jamPulse` など) が別
5. **ハック・探信などの個別機能** — 敵は `enemyHackAI`/`firePingFromEnemy` の別実装 (値は同じ)
6. **艦種表 `ENEMY_COMBAT`** — 艦載機 (戦闘機) 用に残る (回頭・速さ・連射の表)。戦艦では 3連装の数・武器選びには使わない
7. **勝率の偏り (残り)** — 鏡合わせ(攻撃的・標準 20分・決着のうち 自機勝/敵勝): 攻撃型 12/4・潜航型 22/7・空母 5/0。1の差が主因と推測 (未検証)

## 今後の進め方 (案)
- 1を解消するには、自機COMと敵の判断を **1つの関数** (行為者を引数に取る) にまとめる。自機側 `comPilotStep` を基準に、敵の `Ship.update` から判断を取り出して同じ関数を呼ぶ形が候補 (大きな改修)
- 各段階で 鏡合わせ (`tools/mirror_stats.js`) と決闘で 自機勝/敵勝 が五分になるかを確認する

## 2. 設計: 行為者 (Actor) を引数に取る
判断関数が触る物を3つの口に分け、自機用・敵用の「アダプタ」が同じ形で返す。判断関数は **グローバルの `player`/`enemies[0]` を直接読まない**。

```
Actor A {
  // 自分の状態 (読むだけ)
  pos, vel, hp, hpF, ship('assault'|'stealth'|'carrier'), P(性格4軸), engine, stance, now
  stock(kind)  ammo(w)  hasWeapon(w)  slots()  droneCount(type)   // 持ち物
  // 知っていること (自分のセンサーだけ)
  est()            // 方位の記録から解いた相手の推定 {x,y,r,age,moving,vx,vy}  (= trackEstimate / e._sa)
  seen()           // 有視界で捉えている相手 (なければ null)
  threats()        // 観測した兆候 (ロック・ミサイル・実弾・信号) = THREATS 相当
  lastHitAgo()  pingedAgo()  clues()   // 被弾・探信・通信途絶
  map: nodes/colonies/derelicts の「自分が知っている」状態 (`_pObs` と同じ考え方)
  // 動かす
  goto(x,y,{speed,why})  stop()  face(ang)  setStance()  setEngine()
  fire(w, x,y)  use(item,{x,y,ang})  order(droneType,kind,x,y)
  say(text,key)    // 思考ログ・試合の記録
  mem              // その行為者だけの作業メモ (c.* / e._* の置き場)
}
```
- `A.est()` は自機なら `_signalAnalysis[lockedSignalId]`、敵なら `e._sa` を **同じ形に整えて** 返す (すでに第39弾で `solveFix`/`trackEstimate` は共有。残るのは「どの信号を追っているか」の選び方)。
- `A.mem` は `c`(自機COM) と `e` (敵) の別名ではなく、**名前空間を持つ1つの辞書** にする (`mem.hunt`, `mem.strat`, `mem.item`…)。現状は `c.hunt` と `e._hunt` のように名前が違い、写し間違いの元。
- 動かす口 (`goto`/`fire`/`use`) だけが自機と敵で実装が違う (自機は `setTarget`/`playerFireWeapon`/`deployDrone`、敵は `Ship._moveHeading`/`_enemyFire`/`useEnemyItem`)。**判断はこの口の外に出さない**。

## 4. スキル化との関係 (オーナー: 「スキルを艦種で限定すべきか」)
結論 (推論を含む): **艦種では限定せず、前提 (持ち物・武器・状況) で使える/使えないを決める。**
- 根拠: 艦種の差はすでに物理に出ている (速さ・耐久・積載・シグネチャ)。スキルは「どう振る舞うか」なので、艦種で縛ると「攻撃型は隠密してはいけない」という人工的な規則になる。実際、第81弾の「艦種の任務」(空母=網、攻撃型=肉薄、潜航型=影追い) も、中身は 艦載機を持つ / 実弾を積む / 速い、という前提で足りる。
- 登録の形 (案):
  ```
  SKILLS.stalk = {
    id, jp, group: 'hunt'|'strat'|'item'|'move',
    needs: A => bool,           // 前提: 持ち物・武器・距離・耐久 (艦種は書かない)
    weight: (A,P) => number,    // 性格4軸と状況から (今の `w.charge` 等をそのまま移す)
    enter(A,ctx), step(A,ctx), exit(A,why),
    cooldown, maxSec
  }
  ```
- 艦種による得手不得手は **重みの中の物理量** で出す (例: 回り込みの重みは `A.speed` と旋回で下がる → 遅い空母は自然に選びにくい)。現状の `cls === 'carrier' ? 0.4 : 1` のような艦種の直書きは、段5で速さ・加速に置き換える。
- オン/オフ: COM対戦の設定画面に「使うスキル」のチェック (自機COM・敵COMで別々)。既定は全部オン。記録 (`meta.cfg`) に残す。
- **新パラメータ** (案・未実装): 欺瞞傾向 (罠・囮を使う頻度)・執拗さ (見失った後に追う時間)・協調性 (ドローン運用)。今は `wake`/`still` などの派生値に隠れている物を、軸として出す。入れるのは段4〜5の後 (スキルの重みが1か所に集まってから)。

## 追記 (2026-11-13): 段1「取りに行く物」へのオーナーの助言
- 人が操作する時は、**最初は一番近い物 (見えているコロニー・ノード) を目指す**。近くにコンテナなどが無ければ、まず最寄りのコロニーかノード。→ 段1の `grabStep(A)` は「見えている/知っている拠点・拾い物のうち最寄り」を基本にし、性格・状況は重みで補正する (遠くの物を性格だけで先に選ばない)。今の自機COM/敵は 性格・距離上限・部品の枠の条件が先に来る (`comEarlyGather`・`partHunt`)。

## 第129弾の確認 (2026-11-13): 「小さい差」3〜6のCOM対戦での実態 (コードで確認)
- 3. 囮(デコイ)への誘引: `personaStrip` が自機COM・敵の両方から `decoy` を外す (空母は 戦闘機・哨戒機・リペアだけ残す) ため、**COM対戦ではどちらもデコイを持たず差は出ない**。人が操作する時だけ自機に `decoy` の道具がある (人の道具として残す)。
- 4. ジャミング: 第89弾で敵のジャミングも自機ミサイルの誘導を乱す (`jamMissileFactorAt`) ようにしてあり、効果は対称。式が2か所にあるだけ (値は同じ)。
- 5. ハック・探信: 値は同じ・実装が別。
- 6. `ENEMY_COMBAT`: 艦載機用だけ。
- **本当に残る差は 1 (操縦の総括・戦略の他の本体) と 2 (ドローンの別実装)**。次はドローン: 自機の `Drone` クラスと 敵の `enemyFighterStep`/`enemyTechStep`/`enemyScoutStep` を1つの動かし方に寄せる。
