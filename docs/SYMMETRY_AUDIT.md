# 自機と敵の「差」の洗い出し (第98弾)

オーナー方針: **自機と敵で 条件・行動原理・アルゴリズム を分けない。差をつける要素は何もない。**
ここでは コードを読んで見つけた差を 直した/残っている に分けて記録する。測り方は `tools/mirror_stats.js` (鏡合わせ) と 1対1の決闘 (霧なし・900u)。

## 残っている差 (未対応)
1. **意思決定が2本のコードに分かれている** — 自機COM (`comPilotStep`/`comHunterStep`/`comStratStep`/`comReactItems`/`comGrabStep`…) と 敵 (`Ship.update`の状態機械/`enemyHunterStep`/`enemyStratStep`/`enemyItemsStep`/`enemyGrabStep`…) は別実装で、重み・しきい値を手で揃えているだけ。決定的な差: 
   - 敵は 信号を聞いたら状態が `hunting`→`combat` へ移り、長く収集をしない / 自機COMは「艦でない信号は気配に数えない」(艦影25%未満・確認した囮) と 取りに行く物を続ける。鏡合わせで **ノードの制圧 自機38回 / 敵0回** (攻撃型)・敵の最初の占有が遅い
   - 戦略: 自機COMだけ 収集・ドローンで探る・霧に潜む・圧倒して狩る・Tech建造 / 敵だけ 索敵行・拠点防衛の一部
   - 退く時: 敵は 潜伏 (`_hiding`) の専用の状態 / 自機COMは戦略「霧に潜む」
2. **ドローン** — 自機は `Drone` クラス / 敵は `enemyFighterStep`/`enemyTechStep`/`enemyScoutStep` の別実装 (値は手で揃えている)。空母の決闘は自機が速く勝つ (戦闘機の運用の差の疑い・未確認)
3. **ミサイルの囮に誘われる** — 敵のミサイルだけ 自機のデコイ (`decoys`・デコイ機) に誘引される。自機のミサイルは敵の囮に誘引されない (敵は同種の物を積まない)
4. **ジャミング** — 敵ミサイルの誘導を乱す式 (`jamMissileFactorAt`) と 自機ミサイルの式 (`Projectile.update` の `jamPulse` など) が別
5. **ハック・探信などの個別機能** — 敵は `enemyHackAI`/`firePingFromEnemy` の別実装 (値は同じ)
6. **艦種表 `ENEMY_COMBAT`** — 艦載機 (戦闘機) 用に残る (回頭・速さ・連射の表)。戦艦では 3連装の数・武器選びには使わない
7. **勝率の偏り (残り)** — 鏡合わせ(攻撃的・標準 20分・決着のうち 自機勝/敵勝): 攻撃型 12/4・潜航型 22/7・空母 5/0。1の差が主因と推測 (未検証)

## 今後の進め方 (案)
- 1を解消するには、自機COMと敵の判断を **1つの関数** (行為者を引数に取る) にまとめる。自機側 `comPilotStep` を基準に、敵の `Ship.update` から判断を取り出して同じ関数を呼ぶ形が候補 (大きな改修)
- 各段階で 鏡合わせ (`tools/mirror_stats.js`) と決闘で 自機勝/敵勝 が五分になるかを確認する
